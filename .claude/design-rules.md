# 디자인 작업 규칙 (로컬 전역 CLAUDE.md 에서 옮김, 2026-09-30)

> 경로 읽는 법: 원문의 `~/.claude/skills/`, `~/.claude/mengto-skills/...`, `~/.claude/tools/kill-ai-slop/skill/` 은
> 이 저장소에서는 전부 `.claude/skills/<스킬이름>/` 이다. 스캐너: `node .claude/skills/kill-ai-slop/scripts/scan.mjs app --skip=15,16,28,30,34`

## 디자인 작업 규칙 (디자인 요청 시 최우선 적용)

**트리거**: 디자인/UI/UX 관련 요청 — 개선, 리뉴얼, 점검, 리뷰, 신규 제작, "다듬어줘", "예쁘게", "전면 개선" 등.

디자인 스킬을 **눈에 보이는 것 하나만 골라 쓰지 말 것.** 아래 4단계를 따른다.

### 1단계 — 목적 분석 (코드 손대기 전)

- **제품 유형**: 내부 업무 도구 / 대시보드 / 랜딩 / 커머스 / 포트폴리오
- **사용자·사용 빈도**: 매일 쓰는 도구인가, 한 번 보고 마는 페이지인가
- **기존 자산**: 운영 중인 서비스인가(→ 기존 스택·톤 유지, 재작성 금지), 신규인가
- **제약**: 스택, 데이터 밀도, 접근성 요구

> 목적이 스킬을 결정한다. 매일 쓰는 내부 도구에 랜딩페이지용 테마(글래스/WebGL/브루탈리즘)를 씌우지 말 것.

### 2단계 — 보유 디자인 스킬 전수 확인 (매번 필수)

**Skill 툴에 뜨는 목록만 믿지 말 것.** 미설치 스킬은 목록에 안 뜬다. 아래 3곳을 **전부** 확인한다:

| 경로 | 호출 방법 |
|------|----------|
| `~/.claude/skills/` | Skill 툴로 직접 호출 가능 |
| `~/.claude/mengto-skills/agent-skills/{ui,web-design,media}/` | **다수 미설치 → SKILL.md 를 직접 Read** |
| `<프로젝트>/.claude/skills/` | 그 프로젝트 파일 작업 중일 때만 목록에 노출 |

### 3단계 — 큐레이션 후 보고

목적에 맞는 스킬 **2~4개**를 고르고, **선정 이유 + 제외 이유를 먼저 보고**한 뒤 적용한다.

| 상황 | 우선 스킬 |
|------|----------|
| 기존 화면 개선·리디자인 | `mengto ui/redesign-existing-projects` (Scan→Diagnose→Fix, 재작성 금지) |
| 신규 화면·컴포넌트 | `frontend-design` + `ui-ux-pro-max --design-system` |
| 접근성·체크리스트 검증 | `ui-ux-pro-max` (CSV DB + CLI) |
| 미니멀·절제된 톤 | `mengto ui/minimalist-ui` |
| 그림자·테두리·블러 등 개별 효과 | `mengto web-design/*` (`beautiful-shadows` 등) |
| 시안·이미지 → 코드 | `mengto ui/image-to-code` |
| 대외 랜딩·소개·공유카드 | 아래 「안티 슬롭」 B묶음 + `taste-skill`(설치 시 `design-taste-frontend`) |
| 기존 화면 AI 티 점검 | 아래 「안티 슬롭」 C — `kill-ai-slop` 스캐너 |

### 4단계 — 충돌 시 우선순위

1. **이 CLAUDE.md 의 지시** (사용자 지시 = 최우선)
2. 스킬 지침
3. 기본 동작

예: mengto·taste-skill 둘 다 "Lucide는 AI 기본값이니 Phosphor를 써라"고 하지만, 아래 아이콘 규칙
(**기존 프로젝트는 Lucide 유지 · 신규 대외 화면만 다른 패밀리 허용**)이 우선한다.
근거: 10개 프로젝트 305파일이 이미 Lucide고, 그 규칙은 *랜딩 심미성* 논리라 내부 업무 도구에는
오히려 손해다(아이콘이 흔한 게 학습비용 0이라는 뜻).

## 전역 스킬

### ui-ux-pro-max (규칙 DB · 검증용)

UI/UX 디자인 인텔리전스 스킬. 67가지 스타일, 96가지 팔레트, 57가지 폰트 페어링, 25가지 차트, 13가지 스택 지원.

**용도**: 위 3단계 큐레이션에서 **접근성·체크리스트 검증**과 **디자인 시스템 생성**(`--design-system`)에 사용. 단독 자동 적용이 아니라 큐레이션 결과로 선택한다.

**아래 체크리스트는 스킬 선택과 무관하게 모든 UI 작업에 상시 적용된다.**

#### 적용 우선순위

| 우선순위 | 카테고리 | 수준 |
|---------|---------|------|
| 1 | 접근성 (Accessibility) | CRITICAL |
| 2 | 터치 & 인터랙션 | CRITICAL |
| 3 | 성능 | HIGH |
| 4 | 레이아웃 & 반응형 | HIGH |
| 5 | 타이포그래피 & 색상 | MEDIUM |
| 6 | 애니메이션 | MEDIUM |
| 7 | 스타일 선택 | MEDIUM |
| 8 | 차트 & 데이터 | LOW |

#### 핵심 규칙

**접근성 (CRITICAL)**
- 색상 대비 최소 4.5:1 (일반 텍스트 기준)
- 모든 인터랙티브 요소에 포커스 링 표시
- 의미 있는 이미지에 alt 텍스트
- 아이콘 전용 버튼에 aria-label
- Tab 순서는 시각적 순서와 일치

**터치 & 인터랙션 (CRITICAL)**
- 최소 44×44px 터치 타겟
- 비동기 작업 중 버튼 비활성화
- 에러 메시지는 문제 발생 위치 근처에 표시
- 클릭 가능 요소에 `cursor-pointer` 필수

**성능 (HIGH)**
- 이미지: WebP, srcset, lazy loading 사용
- `prefers-reduced-motion` 체크
- 비동기 컨텐츠를 위한 공간 미리 예약

**레이아웃 & 반응형 (HIGH)**
- 모바일 본문 최소 16px
- 가로 스크롤 금지
- z-index 스케일 정의 (10, 20, 30, 50)

**타이포그래피 (MEDIUM)**
- 본문 line-height: 1.5–1.75
- 한 줄 65–75자 제한

**애니메이션 (MEDIUM)**
- 마이크로 인터랙션: 150–300ms
- `transform`/`opacity` 사용 (width/height 금지)

#### 전문가 UI 필수 체크리스트

### 안티 슬롭 (taste-skill · kill-ai-slop 기반, 2026-08-28 도입)

출처: [taste-skill](https://github.com/Leonxlnx/taste-skill) 81.5k★ · [kill-ai-slop](https://github.com/yetone/kill-ai-slop) 1.1k★.
**두 저장소 모두 「랜딩·포트폴리오」용이다.** 대시보드·데이터테이블·다단계 폼은 taste-skill 스스로
적용 대상에서 제외한다(§13). 그래서 아래를 두 묶음으로 나눈다.

#### A. 전 화면 상시 적용

- **AI 기본 색을 쓰지 않는다** — 인디고→바이올렛 그라디언트(`#6366f1→#a855f7`), 순수 검정
  `#000000`(→ zinc-950), 과채도 액센트. 액센트는 **프로젝트당 하나**, 전 섹션 동일하게.
- **제목에 그라디언트 텍스트(`background-clip:text`) 금지.** 위계는 크기·굵기·여백으로 만든다.
- **위계는 최소 1.25배.** 섹션 제목이 본문과 같거나 작으면 제목이 아니다.
- **가짜 데이터 금지** — "John Doe", "Acme/Nexus/SmartFlow", `99.99%`, `1234567`.
  숫자는 측정된 것만. 근거 없으면 아예 넣지 않는다.
- **빈말 동사 금지** — "혁신적", "seamless", "차세대", "Elevate". 구체적인 동사로.
- **`transition-all` 금지** — 바뀌는 속성만 명시(기존 `transition-colors duration-200` 규칙과 동일).
- **상태는 말로 먼저.** 빨강/노랑/초록 신호등 3색을 팔레트처럼 쓰지 않는다.

#### B. 대외 노출 화면 한정 (랜딩 · 소개 · 공유카드)

대상 예: 메추리얼 공유카드, 오렌지볼 `/about`, 온볼 소개 페이지.

- **히어로는 첫 화면에 들어간다** — 제목 2줄 이내, 부제 20단어·4줄 이내, CTA가 스크롤 없이 보인다.
  상단 패딩 `pt-24` 이하. 히어로 텍스트 요소는 **최대 4개**(eyebrow/브랜드띠 · 제목 · 부제 · CTA).
- **eyebrow(제목 위 작은 대문자 라벨)는 3섹션당 1개**까지. 히어로도 1개로 센다.
- **같은 레이아웃 패밀리 반복 금지** — 좌이미지+우텍스트 지그재그 **3연속 금지**.
  8개 섹션이면 최소 4가지 레이아웃.
- **섹션 번호(`01 / 02 / 03`)는 진짜 순서일 때만.** 장식용 번호는 금지.
  (예외: 오렌지볼 `/about` 요강은 참가팀이 "05번 절"로 인용하므로 **유지**)
- **3등분 동일 카드 금지** — 비대칭 그리드나 다른 패턴으로.
- **한글에 `uppercase` 금지** — 효과가 없고 자간만 벌어져 가독성이 나빠진다.
- em dash(`—`) 는 **화면에 보이는 문구**에서 줄인다. 소스 주석·내부 문서는 해당 없음.
  (원문 규칙은 "완전 금지"지만 그건 영문 카피 기준이다. 한글에서는 신호가 약하니 판단해서 적용)

#### C. 감사 도구 — kill-ai-slop 스캐너

기존 화면을 점검할 때만 쓴다. **상시 규칙이 아니다.**

설치 위치: `~/.claude/tools/kill-ai-slop/` (2026-08-28 배치. 웹사이트 폴더는 제거, 스캐너만 보관)

```bash
node "$HOME/.claude/tools/kill-ai-slop/skill/scripts/scan.mjs" <프로젝트>/src --skip=15,16,28,30,34
```

- 오탐이 매우 많다. **후보 목록이지 판정이 아니다** — 반드시 파일을 열어 확인한다
- `--skip` 기본값 이유: 15=주석의 ⚠ 표시, 16=스켈레톤 `animate-pulse`,
  28=스탯 그리드, 30=의미 있는 조문 번호, 34=주석 구분선. 전부 정상 코드다
- 첫 실행 결과: `docs/slop-audit-2026-08-28.md`
