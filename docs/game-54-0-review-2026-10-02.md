# 82-0.com 검토 → KBL 버전 "54-0" 인풋 정리 (2026-10-02)

> 세션 환경에서 82-0.com·소개 기사(ESPN·Aftermath·Substack 등)는 접속 차단이라 **검색 결과 요약**으로 검토했다.
> 실제 화면을 한 번 직접 해 보고 아래 "확인 필요" 항목을 채우면 좋다.

## 1. 82-0.com 은 어떤 게임인가
- 만든 곳: Vaulty Studios (웹 + iOS·안드로이드 앱). 2026년 6월 NBA 트위터에서 바이럴 — 할리버튼·벅스 공식 계정까지 참여. 수익은 Ko-fi 후원(서버비)뿐.
- 목표: 역대 선수 5명으로 **82전 전승(82-0)** 라인업 만들기. (실제 최고 기록은 73-9)

### 진행 순서
1. **슬롯머신 돌리기** → 무작위 **팀 + 연대**(예: 1960년대 워리어스)가 나온다.
2. 그 팀·그 연대 선수 중 **한 명을 고른다** → 내 주전 5자리 중 한 칸에 넣는다.
3. 5라운드 반복. **팀 다시 돌리기 1번, 연대 다시 돌리기 1번**(스킵)만 허용 → 운 + 판단.
4. 5명이 차면 **시즌 시뮬레이션** → "61-21" 같은 성적이 나온다.
5. 결과를 캡처해 SNS 공유("82-0 찍었다", "5승 모자랐다") — 바이럴의 핵심.

### 점수 계산
- 선수마다 **그 연대 안 최고 시즌**의 경기당 득점·리바·어시·스틸·블록 5개를 더해 5명 합계 = **전력 지수(Strength Rating)**.
- 비선형 곡선(승수가 늘수록 1승 더 얻기가 어려움) + 연대별 보정(빠른 시대 숫자 할인) → 82경기 시뮬레이션.
- 옛날에 안 쟀던 스틸·블록은 추정치로 채움.

### 사람들이 좋아한/불평한 점
- 좋아함: 1판 1~2분, 운(슬롯) + 선택(누구를 고를지, 스킵을 언제 쓸지), 결과 한 줄을 공유하기 좋음, "우리 팀 레전드" 이야기 거리.
- 불평: **윌트 체임벌린(60년대 50점·25리바) 한 명만 나오면 나머지가 누구든 82-0** — 단순 합산 공식의 구멍. 포지션·조합·수비가 거의 의미 없음.

## 2. KBL 로 옮길 때 바꿔야 할 것 (우리 데이터로 확인한 사실)

| 82-0 | KBL 사정 | 제안 |
|---|---|---|
| 82경기 | KBL 정규시즌 **54경기**(초창기 21·45경기, 2019-20 43경기) | 이름 **"54-0"**, 시뮬레이션은 54경기 고정 |
| 연대 7개(60~20년대) | KBL 은 1997년부터 → 연대로 나누면 4개뿐(90·00·10·20년대) | 연대 대신 **"시대 구간"** 6개 정도(예: 97~01·02~06·07~11·12~16·17~21·22~26) 또는 **"팀 + 시즌" 하나를 바로 뽑기** |
| 팀 | 구단 매각 시 코드가 바뀜(SBS 40 → KT&G 70), 이름 변경은 유지 | 뽑기 단위는 **그 시즌의 실제 팀**(우리 팀 코드 그대로). 팀-시대 조합 약 50개 |
| 체임벌린 문제 | **훨씬 심함**: 경기당 득점+리바+어시+스틸+블록 상위 100개 시즌 중 **97개가 외국 선수**(1위 피트 마이클 06-07 50.9). 국내 최고는 서장훈 98-99 43.9 | ① **외국 선수 최대 2명**(실제 KBL 규정 느낌, 시대에 따라 1명 옵션) ② 점수를 원숫자 합이 아닌 **그 시즌 안 백분위**로 |
| 연대 보정 | 우리는 이미 시즌 안 백분위·등급을 계산함(레이더 6축·종합 점수, 국내/외국인 풀) | 전력 지수 = 5명의 **종합 점수(1~99)** + 축 보너스 → 시대 보정이 저절로 됨 |
| 포지션 무시 | 우리는 선수 포지션(G/F/C)을 가지고 있음 | 슬롯을 **가드 2·포워드 2·센터 1**로 고정(또는 포지션 안 맞으면 감점) → 조합 고민이 생김 |
| 스틸·블록 추정 | 우리 1차 스탯은 **30개 시즌 전부** 있음 | 추정 불필요 |

### 점수 공식 제안 (예시 — 만들 때 실제 데이터로 맞춘다)
- 선수 점수 = 그 선수 **그 시즌**의 종합 점수(우리 등급 점수 1~99, 표본 기준 충족 선수만 후보).
- 팀 보너스: 레이더 6축(공격·수비·리바운드·슈팅·리딩·효율) 중 **5명 중 최고값**이 높을수록 + / 같은 축만 몰리면 −(예: 슈터 5명 → 리바운드 부족).
- 승률 = 비선형 곡선(평균 99점에 가까워야 54-0). 같은 라인업이면 **항상 같은 결과**(난수 시드 = 라인업)로 해서 "운빨 재시도" 대신 조합 실력으로 경쟁.
- 결과 화면에 "이 팀의 약점: 리딩" 같은 한 줄 → 다시 해 볼 이유.

## 3. 우리 서비스에 심을 때 그림

- **화면 하나**: `/game` (메뉴 "54-0"). 데이터는 이미 있는 `public/cards/{시즌}.json` 만 읽음 → **새 수집·DB 없음**. 원칙 1(화면은 processed 만), 원칙 5(점수 계산은 `lib/` 한 파일)에 맞음.
- 흐름: 슬롯 돌리기(팀 로고 + 시즌 칩이 돌아감) → 후보 선수 카드 목록(사진·등급·유형 라벨) → 코트 그림 위 5자리 채움 → 54경기 결과 + 경기별 승패 점 54개.
- **공유**: 이미 있는 카드 PNG 저장(`useCardSave`) 재사용 → "54-0 라인업" 이미지(5명 사진·팀 로고·성적).
- **오늘의 뽑기(데일리)**: 날짜를 씨앗으로 쓰면 모두 같은 슬롯 결과 → 워들처럼 "오늘 나는 51-3". 서버·DB 없이 가능.
- 연결: 고른 선수 이름 → 선수 상세, 결과 → "비교" 탭으로 두 라인업 선수 비교.
- **안 되는 것**: 전체 순위표(랭킹 보드)·내 기록 저장 공유는 서버 저장소 필요 → 지금 원칙(DB·로그인 없음)과 충돌. 내 최고 기록은 브라우저에만 저장(즐겨찾기와 같은 방식)은 가능.

## 4. 결정 (사용자, 2026-10-02) → 구현 완료 `/game`
범위 IN · 외국 선수 최대 2명 · 시대 구간 7개(같은 구간 반복 가능) · 가드 2/포워드 2/센터 1 · 오늘의 뽑기 없음 · 전승 확률 약 1%.

### (결정 전 질문)
1. **SCOPE.md 에 "게임" 추가 여부** — 지금 IN 목록에 없음(규칙상 만들기 전 확인 필요).
2. 외국 선수 제한: 2명 / 1명 / 제한 없음(대신 점수만 백분위).
3. 뽑기 단위: 시대 구간 + 팀 / 팀 + 시즌 바로.
4. 포지션 슬롯 강제 여부.
5. 데일리 모드를 처음부터 넣을지.
