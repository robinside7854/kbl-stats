# KBL 팬 숏폼(YouTube Shorts) 자동 제작 — 검토와 설계 (2026-10-02)

> 요청: ① 스포츠·농구 숏폼 레퍼런스 수집 ② KBL에 맞춘 숏폼 템플릿 ③ 매일 주제를 골라 만들고 올리는 것까지 전부 자동으로.
> 결론 먼저: **①은 일부만 지금 가능하고 나머지는 조사 워크플로로**, **②·③의 "만들기"까지는 지금 데이터로 거의 전부 자동화할 수 있습니다.** 막히는 곳은 기술이 아니라 **사진 권리**와 **유튜브 업로드 승인(감사)** 두 가지입니다. 그래서 "완전 자동"은 3단계로 나눠 가는 것을 권합니다.
> 이 문서는 검토와 설계만 담았습니다. 코드는 아직 바꾸지 않았습니다.

## 1. 레퍼런스 수집

### 1-1. 지금 확인된 사실 (웹 검색 기준)

- **숏폼은 첫 3초가 전부**: 1~3초 사이에 시청자의 30~50%가 빠지면 알고리즘이 "가치 낮은 영상"으로 보고 노출을 줄입니다. 인사·소개 없이 **가장 강한 장면(숫자)으로 바로 시작**하는 것이 공통 권장입니다. ([aibrify](https://aibrify.com/en/blog/youtube-shorts-retention-curve-playbook), [shortsfast](https://shortsfast.com/blog/faceless-shorts-hooks-retention-2026/))
- **길이**: 잘 되는 쇼츠는 15~35초에 많이 몰려 있고, 30~60초는 이야기가 필요한 주제에서 통합니다. 20초 미만이면 끝까지 보는 비율이 높고, **끝이 처음으로 자연스럽게 이어지는 "루프"** 가 다시 보기를 늘립니다. ([opus.pro](https://www.opus.pro/blog/ideal-youtube-shorts-length-format-retention), [tunepocket](https://www.tunepocket.com/best-length-youtube-shorts/), [joinbrands](https://joinbrands.com/blog/youtube-shorts-best-practices/))
  → 요청하신 30~60초 중 **기본 35~45초**를 권합니다.
- **NBA 쪽 큰 숏폼 채널은 대부분 "경기 영상 클립"** (House of Highlights, Highest Highlights 등 — 플레이오프 클립으로 주간 6천만 뷰대). ([tubefilter](https://tubefilter.com/2022/08/15/top-50-most-viewed-us-youtube-channels-week-of-08-14-2022/), [NBA PR](https://pr.nba.com/nba-youtube-one-billion))
  → **우리는 경기 영상을 쓸 수 없습니다**(중계권). 따라서 우리 자리는 "클립 채널"이 아니라 **"기록·그래픽 채널"** 입니다.
- **기록 그래픽 계열의 대표는 StatMuse**: 선수 얼굴을 **만화풍 일러스트**로 그리고 기록 한 줄로 논쟁을 일으키는 방식으로 X·인스타에서 크게 성공. 사진 권리를 피하면서 "누가 더 낫냐" 댓글 싸움을 만드는 구조가 우리에게 가장 가까운 모델입니다. ([SLAM](https://www.slamonline.com/?p=813914))
- **국내**: KBL 공식 채널(KBL TV)은 하이라이트·예능형(크블식당·퇴근길 등) 중심이고, 기록을 그래픽으로 풀어 주는 **KBL 전문 숏폼 채널은 검색으로 찾지 못했습니다** — 빈자리입니다. 야구 쪽에는 랭킹·기록을 다루는 채널(예: 야구톡톡)이 있습니다. ([고구마팜](https://gogumafarm.kr/?p=10066), [vling](https://vling.net/channel/UCJwI4Fc8yZuuUxKzwrRCDdQ/channel-info))

### 1-2. 레퍼런스 유형별 정리 (우리가 가져올 것)

| 유형 | 대표 예 | 가져올 점 | 우리 데이터로? |
|---|---|---|---|
| 하이라이트 클립 | House of Highlights, KBL TV | 빠른 컷, 큰 자막 | ✕ (영상 권리 없음) |
| 기록 한 줄 + 일러스트 | StatMuse | 얼굴 일러스트 + "이 기록 아는 사람?" 논쟁 | ○ |
| 랭킹 카운트다운 | 야구 랭킹 채널, NBA "Top 5" | 5위 → 1위 순서로 긴장감 | ○ |
| VS 비교 | NBA "누가 더 나았나" 류 | 두 선수 나란히, 항목별 승패 | ○ (비교 탭 그대로) |
| 슛 차트 | ESPN 커크 골즈베리 류 | 코트 위 뜨거운/차가운 구역 | ○ (2006-07부터 보유 — 국내에 거의 없는 자산) |
| 퀴즈 | "이 선수 누구?" | 힌트 3개 → 정답, 댓글 유도 | ○ |
| 그날의 역사 | "N년 전 오늘" | 날짜가 바뀌어 매일 소재 | ○ (한 경기 최다에 날짜 있음) |

### 1-3. 조회수·좋아요 숫자까지 모으려면 (제안: 조사 워크플로)

이 환경에서는 유튜브가 막혀 있어 "실제 조회수 순 목록"은 만들지 못했습니다. 대신 이렇게 하면 자동으로 모입니다:

1. 구글 클라우드에서 **YouTube Data API 키** 하나 발급 (무료) → GitHub 레포 설정의 Secrets 에 `YOUTUBE_API_KEY` 로 저장.
2. 조사 워크플로가 검색어("농구 기록 쇼츠", "KBL 쇼츠", "NBA stats shorts", "야구 기록 쇼츠" 등)로 최근 1년 쇼츠를 조회수 순으로 받아 **조회수·좋아요·댓글·좋아요 비율·길이·제목** 표(`docs/shorts-references.md`)를 만듭니다.
3. 하루 무료 한도(10,000 단위) 안에서 검색 한 번이 100 단위라 수십 번 검색해도 충분합니다.

## 2. KBL 숏폼 템플릿 설계

### 2-1. 공통 뼈대 (40초 기준, 세로 1080×1920, 30fps)

| 시간 | 장면 | 내용 | 규칙 |
|---|---|---|---|
| 0~1.5초 | **훅** | 가장 센 숫자 하나 + 질문 ("한 경기 46점. 누굴까?") | 인사·로고 금지. 첫 프레임부터 숫자 |
| 1.5~6초 | 맥락 | 시즌·팀·왜 대단한지 한 줄 ("KBL 역대 국내 선수 3위") | |
| 6~30초 | 본문 3박자 | 숫자가 올라가는 애니메이션 / 막대 경주 / 레이더 / 슛 차트 | 4~6초마다 화면 전환 |
| 30~37초 | 반전·결론 | "그런데 이 선수, 신인이었다" | |
| 37~40초 | 질문 + 루프 | "여러분 생각은? 댓글로" → 첫 장면과 이어지는 마지막 프레임 | 다시 보기 유도 |

- **안전 구역**: 쇼츠 화면은 오른쪽(좋아요·댓글 버튼)과 아래 25%(제목·채널명)가 가려집니다. 중요한 숫자·이름은 **위 15% ~ 아래 25% 사이, 가운데**에만.
- **디자인**: 사이트와 같은 글꼴(Pretendard)·팀 색·등급 색을 그대로 써서 "사이트에서 본 그 카드"가 영상으로 움직이게 → 채널과 사이트가 서로 홍보됩니다.
- **자막은 화면에 박아서**(소리 없이 보는 사람이 많음). 하단 고정 문구: "기록: KBL 공식 홈페이지 · 비영리 팬 채널".
- **소리**: 배경음은 유튜브 오디오 보관함(무료, 유튜브용 사용 허락) 곡을 몇 개 골라 레포에 넣어 돌려 씀. 내레이션은 선택(§3-3).

### 2-2. 포맷 7개 (요일별로 돌려 "매번 같은 템플릿" 판정을 피함)

| 요일 | 포맷 | 예시 제목 | 쓰는 데이터 (이미 있음) |
|---|---|---|---|
| 월 | **주간 TOP 5** | "지난주 득점 TOP 5, 1위는 의외" | 이번 시즌 경기별 기록(매일 수집 중) / 개막 직후엔 지난 시즌 |
| 화 | **VS 대결** | "허웅 vs 허훈, 25-26 진짜 승자는?" | 비교 탭 계산(`compareCardEntries`), 레이더 6축 |
| 수 | **슛 차트 해부** | "워니가 슛을 쏘는 곳은 여기" | 슛 구역·리그 대비 뜨거운/차가운 구역(`zoneHeat`) |
| 목 | **N년 전 오늘** | "17년 전 오늘, 한 경기 51점" | 한 경기 최다 + 날짜(`gameDate`) |
| 금 | **퀴즈: 이 기록 누구?** | "힌트 3개로 맞혀 보세요" | 통산 순위·수상·프로필(출신교·키) |
| 토 | **이정표 카운트다운** | "워니, 3점 300개까지 2개" | 다음 이정표(`nextMilestones`) — 경기 전날 올리면 시의성 |
| 일 | **역대 / 54-0 드림팀** | "역대 최강 가드 5명" / "이 라인업 54전 몇 승?" | 역대 통산 순위, 54-0 게임 풀 |

**끼어들기(우선)**: 아래 일이 생기면 그날 포맷보다 먼저 만듭니다.
- 어제 경기에서 **시즌 최다·커리어 하이** 경신 (경기별 기록 + 한 경기 최다)
- **이정표 달성** (어제 경기로 1,000점·300블록 등을 넘김)
- **오늘 생일**인 현역 선수 (`birthdaysOn`) — 생일 축하는 반응이 좋고 논쟁이 없음

**시기**: 2026-27 정규리그가 **10월 3일(내일) 개막**, 2027-04-11까지 팀당 54경기입니다. ([isplus](https://isplus.com/article/view/isp202609150096)) 시즌 중엔 "어제 경기" 소재가 매일 생기고, 비시즌(4~9월)엔 역대·퀴즈·슛 차트 비중을 높입니다.

### 2-3. 주제 고르는 규칙 (자동)

1. 오늘 끼어들기 후보가 있으면 그중 "얼마나 놀라운가" 점수(리그 순위·커리어 하이 여부·연차) 1위.
2. 없으면 요일 포맷에서 후보 여러 개를 만들어 점수순.
3. **최근 14일 안에 나온 선수·최근 30일 안에 나온 같은 주제는 제외** (같은 선수만 계속 나오는 것 방지).
4. 팀이 한쪽에 몰리지 않게 주간 팀 등장 횟수 제한 (10개 구단 팬 모두 보게).

## 3. 자동화 설계

### 3-1. 전체 흐름

```
[매일 새벽] 기존 수집(fetch.yml) — 지금 그대로
      ↓
[아침 7시] 숏폼 워크플로(shorts.yml, 새로 만듦)
  ① 주제 고르기   data/processed → 오늘의 에피소드 1개 (숫자·선수·장면 목록)
  ② 대본 쓰기     숫자는 데이터 그대로, 문장만 AI가 다듬음 → 숫자 대조 검사
  ③ (선택) 목소리  한국어 TTS → 음성 파일
  ④ 렌더링        Remotion 으로 mp4 (약 3~8분)
  ⑤ 결과 전달     단계에 따라: 파일 받기 → 비공개 업로드 → 예약 공개
```

- 사이트 원칙 그대로: 영상 쪽도 **`data/processed` 만 읽고** KBL 서버를 부르지 않습니다. 지표 계산은 이미 있는 `lib/` 함수를 그대로 씁니다 → 사이트와 영상의 숫자가 항상 같습니다.
- 매일 결과는 `shorts/episodes/2026-10-03/` 에 **에피소드 정보(JSON)·대본·제목·설명**만 커밋(영상 파일은 커서 커밋하지 않음 — Actions 결과물로 보관).

### 3-2. AI 대본이 숫자를 틀리지 않게

- AI에게는 "숫자 목록"과 "포맷 틀"만 주고 **문장만** 쓰게 합니다.
- 결과 대본 안의 숫자를 전부 뽑아 에피소드 숫자 목록과 하나씩 대조 → 하나라도 다르면 **AI 문장을 버리고 미리 만든 틀 문장으로 대체**. 기록 채널은 숫자 하나 틀리면 신뢰가 무너지기 때문입니다.
- 비용: Claude API 하루 1회 수 원 수준.

### 3-3. 목소리: 넣을까 말까

| 방식 | 장점 | 단점 |
|---|---|---|
| 자막 + 음악만 | 가장 간단, 실패 지점 적음 | 내레이션 있는 영상보다 끝까지 보는 비율이 낮을 수 있음 |
| AI 목소리(TTS) | 정보 전달력↑ | 발음 오류(외국 선수 이름) → 이름 읽기 사전 필요 |
| 본인 목소리 | 채널 개성 최고, "같은 템플릿 양산" 판정에도 가장 안전 | 매일 녹음 필요 → 완전 자동과 충돌 |

권장: **첫 2주는 자막+음악**으로 시작해 반응을 보고, 이후 TTS를 붙여 비교.

### 3-4. 업로드: 3단계로 가는 이유

유튜브 정책상 **2020년 7월 이후 만든 API 프로젝트는 구글 감사를 통과하기 전까지 올린 영상이 전부 "비공개"로 묶입니다.** 감사는 며칠~몇 주 걸립니다. (업로드 할당량은 2025-12 이후 크게 완화되어 하루 1개는 문제 없음.) ([timetopost](https://timetopost.co/blog/how-to-upload-videos-youtube-api), [bundle.social](https://bundle.social/blog/youtube-api-quota-exceeded-limits-fixes))

| 단계 | 하는 일 | 사람이 할 일 | 기간 |
|---|---|---|---|
| **1단계: 반자동** | 매일 영상·제목·설명·태그까지 자동 생성 | 폰에서 파일 받아 유튜브 앱으로 올리기 (약 2분) | 첫 2~4주 — 포맷별 반응 확인 |
| **2단계: 자동 업로드(비공개)** | API로 비공개 업로드 + 제목·설명 자동 입력 | 유튜브 스튜디오 앱에서 확인 후 "공개" 한 번 누르기 = **검수 단계** | 감사 신청과 동시에 |
| **3단계: 완전 자동** | 감사 통과 후 예약 공개(오후 6시 등)까지 자동 | 이상하면 내리기만 | 감사 통과 후 |

> 2단계의 "공개 버튼 한 번"은 오히려 남겨 두기를 권합니다. 숫자 오류·민감한 날(선수 부상·사망 소식이 있던 날 등) 걸러 낼 사람 눈이 하나 있는 것이 채널 신뢰에 훨씬 안전합니다.

### 3-5. 유튜브 "양산형 콘텐츠" 정책

2025-07-15부터 유튜브는 "템플릿으로 찍어 낸 듯 영상마다 차이가 거의 없는" 콘텐츠를 **수익 창출 불가**로 명시했습니다(채널 전체 수익 중단 가능). 기준은 "보통 시청자가 영상마다 내용이 다르다고 분명히 느끼는가"입니다. ([YouTube 고객센터](https://support.google.com/youtube/answer/1311392), [netinfluencer](https://www.netinfluencer.com/youtube-cracks-down-on-mass-produced-content-monetization-targeting-shorts-spam/))
→ 대응: 포맷 7개 순환, 주제·선수 중복 제한, 장면 구성도 포맷마다 다르게. 지금은 수익 창출을 하지 않으니 당장 문제는 아니지만, 나중을 위해 처음부터 다양하게 만듭니다.

## 4. 가장 중요한 결정: 선수 사진

사이트는 KBL 사진을 **링크로 불러와 보여 주기만** 합니다(레포에 복사 안 함, 끄기 스위치 있음). 영상은 사진을 **영상 파일 안에 복제해 유튜브에 배포**하는 것이라 한 단계 더 나아갑니다.
- 사진 저작권: KBL·구단.
- 선수 초상·이름: 2022년부터 부정경쟁방지법이 **퍼블리시티권**(유명인의 이름·얼굴의 경제적 가치)을 보호하며, 판단 기준은 "팬심"이 아니라 "경제적 이익 침해"입니다. ([nepla](https://www.nepla.ai/wiki/지식재산/부정경쟁/퍼블리시티권-관련-자주-묻는-질문-초상권과의-차이-및-굿즈-제작-시-법적-문제-해결-방안-54gnvy5gxn1p))
- 비영리 팬 채널로 기록을 소개하는 정도는 흔하지만, **수익 창출을 켜는 순간 성격이 바뀝니다.** (법률 판단은 아니며, 사업화 단계에서 변호사 검토 항목으로 이미 적어 둔 것과 같은 선)

선택지:

| 안 | 내용 | 위험 | 권장 |
|---|---|---|---|
| A. 사진 없이 | 사이트의 **유니폼 그림(팀 색+등번호)**·이니셜·실루엣·슛 차트·숫자로만 | 가장 낮음 | **시작은 이것** |
| B. 공식 사진 + 출처 표기, 수익 없음 | 사이트와 같은 사진 사용 | 저작권 신고로 영상 삭제·경고 가능(경고 3회면 채널 삭제) | A로 반응 확인 후 고민 |
| C. KBL 허락 받기 | KBL 홍보팀에 팬 채널 협조 요청 | — | 구독자가 생긴 뒤 시도. 수익화 전엔 어차피 필요(약관 제23조) |

설계는 사이트처럼 **스위치 하나로 사진을 켜고 끄게** 만들어 두면, 나중에 허락을 받거나 정책을 바꿀 때 코드를 고칠 필요가 없습니다.

### 만들어진 것

```
data/processed ──► scripts/build-short.ts ──► shorts/episodes/{slug}/episode.json  (대본·숫자, 커밋)
                    (lib/shorts.ts 규칙)
                ──► scripts/prepare-short.ts ──► shorts/public/{slug}/  (목소리 mp3·사진·props.json·upload.txt, git 제외)
                ──► shorts/ (Remotion) ──► mp4 1080×1920
GitHub Actions: .github/workflows/shorts-render.yml  — "# 실행 횟수" 를 1 올려 푸시 → mp4 + upload.txt
                → Actions 결과(Artifacts) 와 shorts-renders 브랜치에 저장
```

장면: 표지(TOP 5 사진 5장) → 5위 … 1위(순위 숫자·이름·사진 위 경기당 득점·슛 위치 점·득점 출처 막대·한 줄 특징) → 다섯 명 막대 비교 → "여러분 팀 에이스는 어떤 유형?" + 다섯 명 요약. 장면 길이는 목소리 길이에 맞춰 자동(약 48~52초).

한 줄 특징 규칙(`pickCallouts`): 다섯 명 중 출처 비중 1위 또는 경기당 출처 득점 1위(비중 20% 이상인 출처만) → 없으면 가장 큰 비중이 40% 미만이면 "균형형". 2025-26 결과: 이정현 "자유투로만 4.5점", 허웅 "3점으로만 8.4점", 안영준 "페인트 45.5%", 허훈 "페인트 38.6% · 3점 36.1%"(균형형), 서명진 "3점 51.8%".

1단계(지금)는 손으로 올리므로 **연동할 것이 없습니다.** 채널은 사용자가 정합니다 — 권장: 지금 쓰는 구글 계정 아래 **새 브랜드 계정 채널**(개인 이름이 드러나지 않고, 나중에 다른 사람에게 관리 권한을 줄 수 있음). 2단계(API 비공개 업로드)에서 그 채널로 구글 로그인을 한 번 하면 됩니다.
